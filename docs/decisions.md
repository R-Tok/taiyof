# 開発の決め事

太陽不動産株式会社の公式サイト更新で、実装前に揃える方針の正本です。
ステータスは次の3つです。

- **確定**: 依頼または確認で決まっていること
- **仮決定**: 確認前に開発を止めないための暫定。回答があればここを更新する
- **未決定**: まだ選んでいないこと

新しいページや共通部品を作る前に、このファイルの確定と仮決定を読むこと。

URL ツリーの詳細は [`docs/site-map.md`](./site-map.md) を参照。

## 確定

### 進め方

- このリポジトリでフロントを中心に開発する。
- 技術は Next.js App Router、TypeScript、Tailwind CSS。モバイルを含むレスポンシブにする。
- 最初は仮デザインで実装し、後から Figma などで作ったデザインに差し替える。
- 物件情報やお知らせに加え、会社概要も運用者が CMS で更新できるようにする。CMS の候補は microCMS。
- CMS を接続するまでは、原稿を `lib/` の TypeScript 定数で管理する。接続時は取得処理を差し替え、表示側の形はできるだけ維持する。
- microCMS 連携は **お知らせ（`/infos`）から先に** つなぐ。物件 API はスキーマ確定後。
- microCMS の API ID は、お知らせ `infos`、売買物件 `deal`、賃貸物件 `rent`。物件詳細の URL は slug フィールドがあればそれを使い、無ければコンテンツ ID。
- 詳細 URL 用にコンテンツへ **`slug` フィールド** を持たせる（コンテンツ ID は URL に使わない）。
- 反映は **一定時間キャッシュ + 公開時 Webhook で再生成**。
- 環境変数未設定時は現行の `lib/` 定数を表示する。取得失敗時はエラー画面にする。
- API キーは `NEXT_PUBLIC_` を付けず、Server Component / `lib/` からのみ使う。
- 仮デザインはライト固定。白背景、本文は墨色、見出しのアクセントは紺。フォントは Noto Sans JP。
- 共通ヘッダーはロゴを左端に置く。フッターは会社情報。どちらも仮デザインで、後から差し替える。
- トップページは仮デザイン。ファーストビューは大きなメインビジュアル。写真が用意できたら `public/hero/town.svg` を差し替える。
- 言語は日本語のみ。`html` の `lang` は `ja`。
- URL は末尾スラッシュなし（例: `/company`）。現行の `index.html` からのリダイレクトは公開前に設計する。
- 公開作業は開発者が行う。会社側の更新は microCMS の文章が中心で、サイト本体の公開は年に数回程度。
- サイトは新しい公開先に載せる。現行 URL から変わってもよい。現行サーバー契約をやめることもあり得る。
- メールアドレス（独自ドメイン）は変えない。受信箱の契約は、サイトの公開先とは別に残す。
- 問い合わせの差出人は送信サービス側のアドレスでよい。受信先は、開発中は Gmail、本番は現行の独自ドメイン。

### サイトマップ・URL

- **実装済**: `/company`、`/infos`、`/infos/[slug]`、`/deal`、`/deal/land`、`/deal/house-mansion`、`/rent`、`/rent/apartment`、`/rent/mansion`、`/rent/house`、`/rent/store-warehouse`、`/properties/[slug]`。カテゴリ定義は `lib/property-routes.ts`。売買は `deal` API、賃貸は `rent` API。アパート・マンションの間取り絞り込みは `layout_category` を `/rent/apartment/1` などのパスに対応させる。
- **単一ページ**: `/contact`（実装済）。`/privacy-policy` は未実装。
- **物件からの問い合わせ**: `/contact?param=` に物件名を渡し、「問い合わせ物件名」欄へ反映（現行 `contact/index.php?param=` 互換）。
- **売買ルート**: `/deal` は `app/deal/[[...category]]` に統合。Next.js 16 では `/deal/page.tsx` と optional catch-all の併存不可。
- **HTML サイトマップ**: 公開前にリンク一覧だけの簡易版 `/sitemap` を作る。機械向け `sitemap.xml` は別途検討。
- **賃貸ハブ**: `/rent`。小分類は `/rent/apartment/{1|2|3}`、`/rent/mansion/{1|2|3}`、`/rent/house`、`/rent/store-warehouse`。
- **売買ハブ**: `/deal`。小分類は `/deal/land`、`/deal/house-mansion`。
- **物件詳細**: 賃貸・売買共通で **`/properties/[slug]`** のみ（旧案の `/123456` は使わない）。
- **間取りグループ**: パス末尾の `1` / `2` / `3` は、それぞれ 1K・1DK・1LDK / 2K・2DK・2LDK / 3K・3DK・3LDK の **表示用グループ**。
- **一覧の実装**: `app/rent/[[...category]]` と `app/deal/[[...category]]` の catch-all。許可するパス組み合わせは `lib/` の定数テーブルでホワイトリストし、未定義は 404。
- **絞り込み**: カテゴリはパスで表現。家賃・エリア等の追加条件は **将来クエリ**（例: `?maxRent=`）で足す。当面はカテゴリに属する物件を並べる最小実装から始める。
- **お知らせ**: パスは `/infos`（旧案 `/info` は使わない）。microCMS API ID `infos` から取得し、接続前のローカル2件と並べて表示する。本文は CMS が HTML、ローカルはプレーンテキスト。

### 実装の置き場所

- ルートは `app/`。
- サイト共通 UI は `components/`。ページ固有の部品が増えたら `app/<path>/_components/`。
- 原稿・カテゴリ定義は `lib/`（物件カテゴリは `lib/property-routes.ts` 等を想定）。
- 見た目だけの静的なページは Server Component。操作が必要な箇所だけ Client Component。

## 仮決定

| 項目 | 暫定 | 理由 |
| --- | --- | --- |
| サイトの公開先 | Vercel | Next.js と相性がよく、公開作業が少ない。現行の PHP サーバーではこのアプリを動かしにくい |
| メール送信 | Resend。開発中の差出人は `onboarding@resend.dev` | 開発の値は `.env.local`。本番の値は Vercel の Production。記載先は `docs/email-env.md` |

## 未決定

- 取引銀行の表記。現行は「第四銀行・大光銀行・上越信用金庫」のまま転記している。
- トップ `/` の構成と、物件の見せ方。
- 一覧の並び順、クエリパラメータ名、フィルタ UI。
- microCMS のスペース名・サービスドメイン（ローカルは `.env.local`、Git には入れない）。
- お知らせ API のフィールド確定（タイトル・本文・画像・slug・公開日時の API 名）。
- 物件 API のフィールドとカテゴリ（`deal/house-mansion` 等）の持ち方。
- Webhook 用の再検証シークレットと、公開先の環境変数設定。
- 現行契約の内訳。ドメイン、Web、メールが同一契約か。メールだけ残せるか。契約先名が分かれば確認する。
- 現行 URL から新 URL への 301 対応表。URL を変えてよい方針のため、同じドメインを使うかは公開時に決める。
- Figma 等のデザイン適用順。
